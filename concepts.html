COMPUTING CONCEPTS

개념학습

컴퓨터가 정보를 다루는 방법부터 프로그램을 만들고 웹에서 동작시키는 과정까지 익힙니다. 용어를 검색하거나 관심 있는 주제부터 읽어도 됩니다.

전체 개념을 표시하고 있습니다.

컴퓨터 기초 통신과 웹 프로그램 이해 HTML CSS JavaScript Python 제작·배포 용어

먼저 기억할 흐름: 사람이 입력한 정보 → 프로그램의 명령 처리 → 결과 표시 또는 저장. 웹에서는 브라우저가 화면을 보여주고, 필요하면 네트워크를 통해 서버와 데이터를 주고받습니다.

검색 결과가 없습니다. 다른 단어로 검색해보세요.

1. 컴퓨터 기초

컴퓨터는 정보를 입력받고, 명령에 따라 처리한 뒤, 결과를 보여주거나 저장하는 장치입니다.

컴퓨터는 어떻게 일할까요?

키보드로 글자를 입력하면 프로그램이 그 입력을 처리하고, 화면에 글자를 보여주며, 필요하면 파일로 저장합니다. 이를 입력 → 처리 → 출력 → 저장 흐름으로 생각할 수 있습니다.

  • 입력: 키보드, 마우스, 터치, 카메라
  • 처리: 프로그램의 명령을 실행
  • 출력: 화면, 소리, 인쇄
  • 저장: 파일이나 데이터베이스에 보관

하드웨어와 주요 부품

하드웨어는 직접 만질 수 있는 컴퓨터의 부품입니다.

  • CPU(중앙처리장치): 명령을 읽고 계산·판단합니다.
  • RAM(메모리): 실행 중인 프로그램과 작업 정보를 잠시 담습니다. 전원을 끄면 일반적으로 내용이 사라집니다.
  • SSD/HDD(저장장치): 파일과 프로그램을 전원을 꺼도 보관합니다.
  • GPU(그래픽처리장치): 화면 그림과 대량의 병렬 계산을 처리하는 데 쓰입니다.

소프트웨어와 운영체제

소프트웨어는 컴퓨터가 할 일을 적은 프로그램과 데이터입니다. 운영체제(OS)는 하드웨어와 응용 프로그램 사이를 관리합니다.

Windows, macOS, Linux, Android, iOS가 운영체제의 예입니다. 브라우저, 그림 편집기, 게임은 운영체제 위에서 실행되는 응용 프로그램입니다.

비트와 데이터 크기

컴퓨터의 가장 작은 정보 단위인 비트(bit)는 0 또는 1을 나타냅니다. 보통 8비트가 1바이트(byte)입니다.

텍스트, 사진, 소리도 결국 컴퓨터 안에서는 숫자 데이터로 표현됩니다. KB, MB, GB는 파일이나 저장 공간의 크기를 나타내며, 네트워크 속도에 쓰는 Mbps와는 단위가 다릅니다.

파일·폴더·경로

파일은 이름이 붙은 데이터이고, 폴더는 파일을 정리하는 공간입니다. 경로는 파일이 어디 있는지 나타냅니다.

index.html의 .html처럼 점 뒤의 확장자는 파일 종류를 알려줍니다. HTML에서 assets/style.css라고 쓰면 현재 폴더 안의 assets 폴더에서 파일을 찾습니다.

메모리와 저장장치의 차이

RAM은 지금 사용하는 작업을 빠르게 꺼내 쓰는 작업대에, SSD는 자료를 오래 보관하는 서랍에 비유할 수 있습니다. 저장하지 않은 문서가 사라질 수 있는 이유는 작업 중 정보가 메모리에만 있을 수 있기 때문입니다.

2. 통신과 웹의 작동 방식

통신은 장치들이 규칙에 따라 데이터를 주고받는 일입니다. 인터넷은 여러 네트워크가 연결된 전 세계적인 통신망입니다.

네트워크와 패킷

네트워크는 컴퓨터와 기기들이 데이터를 주고받도록 연결한 것입니다. 큰 데이터는 패킷이라는 작은 단위로 나뉘어 이동한 뒤 목적지에서 다시 조립될 수 있습니다.

공유기(라우터)는 집 안의 기기와 외부 네트워크 사이에서 데이터가 갈 길을 연결하고 안내합니다.

IP 주소와 도메인, DNS

IP 주소는 네트워크에서 장치를 찾아가기 위한 주소입니다. 사람에게 읽기 쉬운 도메인 이름은 웹사이트 주소에 사용됩니다.

DNS는 도메인 이름을 해당 서버의 IP 주소와 연결해 찾아주는 시스템입니다. 전화번호부에서 이름을 찾아 번호를 확인하는 것과 비슷합니다.

브라우저와 서버

브라우저(Chrome, Edge, Safari 등)는 HTML·CSS·JavaScript를 읽어 웹 화면을 보여줍니다. 페이지나 자료를 요청하는 쪽을 클라이언트, 요청을 받아 응답하는 컴퓨터·프로그램을 서버라고 부릅니다.

정적 웹사이트는 저장된 파일을 브라우저에 전달합니다. 로그인, 게시글 저장처럼 사용자마다 다른 데이터가 필요하면 보통 서버 프로그램과 데이터베이스를 함께 사용합니다.

HTTP와 HTTPS

프로토콜은 통신할 때 지키는 약속입니다. 웹의 HTTP는 브라우저와 서버가 요청과 응답을 주고받는 규칙입니다. HTTPS는 통신을 암호화하고 서버의 신원을 확인해 전송 중 정보가 노출되거나 바뀔 위험을 줄입니다.

주소창의 자물쇠 표시는 연결이 HTTPS로 보호됨을 뜻하지만, 웹사이트 자체가 항상 안전하거나 믿을 만하다는 보증은 아닙니다.

URL 읽기

URL은 웹에 있는 자원의 주소입니다. 예를 들어 https://example.com/guide에서 https는 통신 방법, example.com은 도메인, /guide는 자원의 경로입니다.

API와 데이터 교환

API는 서로 다른 프로그램이 정해진 방식으로 기능이나 데이터를 주고받는 연결 규칙입니다. 예를 들어 날씨 페이지가 날씨 API에 도시 이름을 보내고 예보를 받아 화면에 표시할 수 있습니다.

JSON은 데이터를 이름과 값의 쌍으로 표현하는 흔한 형식입니다.

{
  "city": "Seoul",
  "temperature": 22
}

3. 프로그램과 코딩의 기본 개념

프로그램은 컴퓨터가 수행할 명령을 순서와 규칙에 따라 모아둔 것입니다. 프로그래밍은 문제를 작은 단계로 나누고, 실행 가능한 코드로 표현하고, 결과를 확인하며 개선하는 과정입니다.

코드와 프로그래밍 언어

소스 코드는 사람이 프로그래밍 언어로 작성한 명령입니다. 컴퓨터는 CPU가 이해하는 기계어로 동작하므로, 언어와 실행 도구가 코드를 해석하거나 변환합니다.

Python과 JavaScript는 실행 도구가 코드를 해석하며 실행하는 방식으로 자주 사용됩니다. Java와 C 계열은 별도의 컴파일 과정이 흔합니다. 언어에 따라 실제 실행 과정은 다를 수 있습니다.

알고리즘

알고리즘은 문제를 해결하기 위한 명확한 순서와 규칙입니다. 요리법처럼 “재료 준비 → 섞기 → 굽기”로 단계화할 수 있습니다. 코드를 쓰기 전에 입력, 처리, 결과를 먼저 적어보면 구현이 쉬워집니다.

변수와 상수

변수는 프로그램이 실행되는 동안 값을 보관하고 이름으로 다시 사용하는 공간입니다. 상수는 정해둔 뒤 바꾸지 않으려는 값을 표현할 때 씁니다.

user_name = "민지"
score = 10

자료형

자료형은 값의 종류와 할 수 있는 작업을 구분합니다.

  • 문자열: 글자 데이터, 예: "안녕하세요"
  • 정수·실수: 숫자 데이터, 예: 7, 3.14
  • 불리언(Boolean): 참 또는 거짓, 예: true
  • 목록·배열: 여러 값을 순서대로 담음
  • 객체·딕셔너리: 이름과 값의 관계로 정보를 묶음

조건문

조건문은 조건의 참·거짓에 따라 실행할 코드를 선택합니다. 예를 들어 비밀번호가 맞으면 로그인하고, 틀리면 오류를 보여주는 식입니다.

if score >= 60:
    print("통과")
else:
    print("다시 도전하세요")

반복문

반복문은 같은 종류의 작업을 여러 번 수행합니다. 정해진 목록의 항목을 하나씩 처리할 때는 for, 조건이 참인 동안 반복할 때는 while을 사용할 수 있습니다.

함수

함수는 특정 작업을 이름 붙여 묶은 코드입니다. 입력값을 받을 수 있고, 처리를 마친 뒤 결과를 돌려줄 수 있어 반복 사용과 수정이 편합니다.

def greet(name):
    return f"안녕하세요, {name}님"

print(greet("민지"))

오류·버그·디버깅

오류는 코드가 실행되지 않거나 예상한 결과가 나오지 않는 상황입니다. 코드의 잘못된 동작을 흔히 버그라고 합니다. 디버깅은 오류 메시지, 입력값, 실행 흐름을 확인해 원인을 찾고 고치는 과정입니다.

오류가 나면 메시지를 처음부터 읽고, 문제가 난 파일과 줄을 찾고, 가장 최근에 바꾼 부분부터 작은 단위로 확인합니다.

4. HTML — 웹페이지의 구조

HTML(HyperText Markup Language)은 웹페이지의 제목, 문단, 링크, 이미지, 입력란 등 콘텐츠의 구조와 의미를 표현하는 마크업 언어입니다. 꾸밈은 주로 CSS, 동작은 주로 JavaScript가 담당합니다.

태그·요소·속성

태그는 꺾쇠 괄호로 표시하며, 요소는 태그와 그 안의 내용을 합친 단위입니다. 속성은 요소에 추가 정보를 줍니다.

<a href="https://example.com">사이트 방문</a>

여기서 <a>는 링크 요소, href는 링크 주소를 담는 속성입니다. 일부 요소는 <img>처럼 별도 닫는 태그가 없습니다.

HTML 문서의 기본 구조

  • <!doctype html>: 표준 HTML 문서임을 브라우저에 알립니다.
  • <head>: 제목, 문자 인코딩, CSS 연결 등 문서 정보를 둡니다.
  • <body>: 사용자에게 보이는 내용을 둡니다.
  • <meta charset="utf-8">: 한글 등 문자를 올바르게 표시하는 문자 인코딩을 지정합니다.

시맨틱 HTML과 접근성

시맨틱 태그는 콘텐츠의 역할을 이름으로 설명합니다. <nav>는 내비게이션, <main>은 주요 내용, <button>은 동작 버튼입니다.

의미에 맞는 태그와 이미지 설명(alt), 폼 입력의 라벨을 사용하면 보조기기와 키보드를 쓰는 사람도 이용하기 쉽습니다.

폼과 입력

<form>은 사용자 입력을 모으고, <input>, <select>, <textarea>는 입력 종류에 따라 값을 받습니다. 입력을 받는다고 자동으로 서버에 저장되는 것은 아닙니다. 저장하려면 별도의 JavaScript와 저장소 또는 서버가 필요합니다.

5. CSS — 화면의 디자인과 배치

CSS(Cascading Style Sheets)는 HTML 요소가 어떻게 보일지 정합니다. 글자 색, 크기, 간격, 배치, 화면 크기에 따른 디자인을 지정합니다.

선택자·속성·값

선택자로 꾸밀 HTML 요소를 고르고, 중괄호 안에 속성과 값을 작성합니다.

.notice {
  color: navy;
  font-size: 18px;
}

.notice는 notice라는 class를 가진 요소, color는 속성, navy는 값입니다.

class와 id

class는 여러 요소에 같은 스타일을 적용할 때 쓰며 CSS에서는 점(.)으로 선택합니다. id는 페이지에서 특정 요소를 구분할 때 쓰며 샵(#)으로 선택합니다.

.card { padding: 16px; }
#main-title { color: navy; }

박스 모델

브라우저는 대부분의 HTML 요소를 상자처럼 배치합니다. 안쪽 내용(content) 바깥에 안쪽 여백(padding), 테두리(border), 바깥 여백(margin)이 있습니다.

box-sizing: border-box;를 사용하면 지정한 너비에 안쪽 여백과 테두리를 포함해 크기 계산이 쉬워집니다.

Flexbox와 Grid

Flexbox는 한 방향(행 또는 열)으로 요소를 정렬하고 간격을 조절할 때 편합니다. Grid는 행과 열이 있는 격자형 레이아웃을 만들 때 유용합니다.

.menu { display: flex; gap: 12px; }
.cards { display: grid; grid-template-columns: repeat(2, 1fr); }

반응형 웹

반응형 디자인은 화면 너비에 따라 콘텐츠 배치와 크기가 적절히 바뀌는 디자인입니다. 모바일 화면에서도 가로로 넘치지 않도록 너비, 글자 크기, 열 개수를 조정합니다.

@media (max-width: 600px) {
  .cards { grid-template-columns: 1fr; }
}

6. JavaScript — 웹페이지의 동작

JavaScript는 웹브라우저에서 실행되어 사용자 입력에 반응하고 화면을 바꾸는 프로그래밍 언어입니다. 이름에 Java가 들어가지만 Java와는 서로 다른 언어입니다.

값과 변수

const는 다시 다른 값을 대입하지 않을 변수, let은 값이 바뀔 수 있는 변수에 사용합니다. 문자열, 숫자, 참·거짓, 배열, 객체 등의 값을 다룹니다.

const title = "첫 페이지";
let clickCount = 0;
clickCount = clickCount + 1;

DOM과 화면 바꾸기

DOM(문서 객체 모델)은 브라우저가 HTML을 프로그램에서 다루기 쉬운 구조로 표현한 것입니다. JavaScript는 DOM에서 요소를 찾아 글자나 속성을 바꿀 수 있습니다.

const heading = document.querySelector("h1");
heading.textContent = "제목이 바뀌었습니다";

이벤트

이벤트는 클릭, 키 입력, 폼 제출처럼 사용자나 브라우저에서 일어난 사건입니다. 이벤트 처리기(listener)를 연결하면 그 사건에 맞는 코드를 실행할 수 있습니다.

button.addEventListener("click", () => {
  message.textContent = "버튼을 눌렀습니다";
});

함수와 코드 재사용

JavaScript 함수는 function 또는 화살표 표기법으로 작성할 수 있습니다. 자주 쓰는 작업을 함수로 묶으면 중복을 줄이고 수정할 위치를 찾기 쉽습니다.

비동기 처리와 서버 요청

네트워크 요청처럼 시간이 걸리는 작업이 끝날 때까지 화면 전체를 멈추지 않도록 기다리는 방식을 비동기 처리라고 합니다. fetch, Promise, async/await가 자주 사용됩니다. 처음에는 버튼 이벤트와 DOM 조작부터 익히고 나중에 학습해도 됩니다.

7. Python — 읽기 쉬운 범용 프로그래밍 언어

Python은 문법이 비교적 간결해 입문, 자동화, 데이터 처리, 웹 서버 등 여러 분야에서 사용하는 프로그래밍 언어입니다. 웹브라우저 자체에서 실행되는 기본 언어는 JavaScript이며, Python 프로그램은 일반적으로 컴퓨터나 서버에 Python 실행 환경을 설치해 실행합니다.

Python 설치와 실행

Python을 설치하면 코드를 실행하는 인터프리터가 준비됩니다. 코드를 hello.py처럼 .py 파일에 저장하고 터미널에서 실행할 수 있습니다.

python hello.py

설치 환경에 따라 명령이 python3 hello.py 또는 Windows의 py hello.py일 수 있습니다.

들여쓰기는 코드의 구조

Python은 들여쓰기로 조건문이나 함수에 속하는 코드 블록을 구분합니다. 같은 블록 안에서는 들여쓰기 간격을 일관되게 유지하세요. 일반적으로 스페이스 네 칸을 사용합니다.

if score >= 60:
    print("통과")
    print("축하합니다")

Python의 자료형과 모음

  • str: 문자열
  • int, float: 정수와 실수
  • bool: True 또는 False
  • list: 순서가 있고 바꿀 수 있는 목록
  • dict: 키와 값으로 정보를 묶는 사전

모듈·라이브러리·패키지

모듈은 재사용할 코드가 담긴 파일입니다. 라이브러리와 패키지는 다른 사람이 만든 기능을 가져다 쓸 수 있게 묶은 코드입니다. Python의 import로 가져오며, 외부 패키지는 보통 pip로 설치합니다.

import random

print(random.randint(1, 6))

가상환경과 의존성

가상환경은 프로젝트별로 Python 패키지를 분리해 관리하는 공간입니다. 한 프로젝트에서 필요한 패키지를 다른 프로젝트와 섞지 않도록 돕습니다. requirements.txt에는 프로젝트가 사용하는 패키지 목록을 기록할 수 있습니다.

Python과 웹 개발

Python은 브라우저 화면의 기본 언어가 아니라 서버에서 데이터 처리, 로그인, 데이터베이스 연결 같은 작업을 맡는 백엔드에 활용할 수 있습니다. Flask와 Django는 웹 애플리케이션을 만들 때 쓰는 Python 프레임워크입니다.

8. 프로그램 제작과 배포 용어

실제 프로젝트에서는 코드 작성 외에도 변경 이력, 검사, 게시와 유지보수 과정을 함께 다룹니다.

코드 편집기와 터미널

코드 편집기는 코드를 작성하고 읽기 쉽게 색칠해주는 도구입니다. VS Code가 대표적인 예입니다. 터미널은 글자로 명령을 입력해 프로그램이나 개발 도구를 실행하는 창입니다.

Git과 GitHub

Git은 파일의 변경 이력을 기록하고 이전 상태와 비교하는 버전 관리 도구입니다. GitHub는 Git 저장소를 인터넷에 보관하고 협업·공유하는 서비스입니다.

  • 저장소(repository): 프로젝트 파일과 변경 이력의 모음
  • 커밋(commit): 특정 시점의 변경 내용 기록
  • 푸시(push): 내 컴퓨터의 커밋을 원격 저장소에 올림
  • 풀(pull): 원격 저장소의 변경 내용을 내 컴퓨터로 가져옴

테스트

테스트는 프로그램이 요구한 대로 동작하는지 확인하는 과정입니다. 작은 함수 단위로 확인하는 테스트부터 실제 브라우저에서 버튼, 입력, 화면 크기를 확인하는 수동 테스트까지 여러 방법이 있습니다.

호스팅과 배포

호스팅은 웹사이트 파일이나 프로그램을 인터넷에서 접속할 수 있는 서버에 두는 서비스입니다. 배포는 완성한 변경사항을 사용자가 접근할 환경에 공개하는 과정입니다. GitHub Pages는 정적 사이트를 호스팅합니다.

프론트엔드·백엔드·데이터베이스

프론트엔드는 사용자가 직접 보는 화면과 상호작용을 만듭니다. 백엔드는 서버에서 규칙과 데이터를 처리합니다. 데이터베이스는 정보를 구조적으로 저장하고 검색하는 시스템입니다. 규모가 큰 웹서비스는 보통 이 요소들이 서로 요청과 응답을 주고받습니다.

요구사항·리팩터링·유지보수

요구사항은 프로그램이 해야 할 일과 지켜야 할 조건입니다. 리팩터링은 사용자에게 보이는 기능은 유지하면서 코드 구조와 읽기 쉬움을 개선하는 작업입니다. 유지보수는 배포 후 오류 수정, 보안 업데이트, 기능 개선을 계속하는 일입니다.

비밀번호와 비밀 정보 보호

비밀번호, API 키, 토큰은 소스 코드나 공개 저장소에 올리면 안 됩니다. 공개 저장소에 올린 비밀 정보는 삭제해도 이미 복사되었을 수 있으므로 해당 키를 폐기하고 새로 발급해야 합니다. 계정 비밀번호는 서버에서 안전한 해시 방식으로 처리해야 합니다.

UI·UX와 접근성

UI(사용자 인터페이스)는 버튼, 메뉴 등 사용자가 직접 조작하는 화면 요소입니다. UX(사용자 경험)는 서비스를 이용하며 느끼는 전체 경험입니다. 읽기 쉬운 글자, 명확한 버튼 이름, 키보드 조작, 모바일 대응은 모두 사용성을 높입니다.

어떤 순서로 공부하면 좋을까요?

  1. 컴퓨터 기초와 파일·폴더·경로를 익힙니다.
  2. HTML로 제목·문단·링크를 만들고, CSS로 색과 배치를 꾸밉니다.
  3. JavaScript로 버튼과 폼에 동작을 추가합니다.
  4. Python으로 변수·조건문·반복문·함수를 익히고 작은 문제를 해결합니다.
  5. Git으로 변경을 기록하고 GitHub에 올린 뒤 정적 웹사이트를 배포합니다.
  6. 필요해지면 API, 데이터베이스, 서버와 보안 개념을 이어서 학습합니다.
