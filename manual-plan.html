웹제작절차 01

웹사이트 기획

코드를 쓰기 전에 무엇을, 누구에게, 어디까지 만들지 정합니다. 목표와 페이지 목록, 화면 스케치, 폴더 구조를 먼저 정해 두면 이후 작업에서 길을 잃지 않습니다.

난이도 · 입문 예상 시간 · 20분 준비물 · 메모장 또는 종이

1. 무엇을 만들지 한 문장으로 정하기

“웹사이트를 만든다”는 목표는 너무 넓습니다. 아래 세 가지 질문에 답하면서 범위를 좁혀 보세요.

  • 누구에게 보여 줄까요? 친구, 신입 부원, 고객, 채용 담당자처럼 대상을 구체적으로 적습니다.
  • 방문자가 무엇을 하길 바라나요? 소개를 읽는다, 프로젝트를 본다, 연락처를 확인한다처럼 행동으로 적습니다.
  • 첫 버전에서 하지 않을 것은 무엇인가요? 로그인, 결제, 게시판, 실시간 채팅은 처음부터 넣지 않습니다.
기획 메모 예시 
목표: 동아리 활동을 소개하는 3페이지 사이트
대상: 신입 부원과 외부 방문자
첫 버전 범위: 홈, 소개, 연락처
하지 않을 것: 로그인, 결제, 게시판
완료 기준: 휴대폰에서 메뉴가 보이고 연락처 링크가 동작한다
TIP

처음에는 1~3페이지면 충분합니다. 작게 완성해서 인터넷에 올려 본 뒤, 필요한 페이지를 하나씩 추가하는 편이 훨씬 빠릅니다.

2. 페이지 목록과 역할 정하기

페이지마다 “이 화면에서 방문자가 얻는 것”을 한 줄로 적습니다. 메뉴에는 핵심 페이지만 넣고, 5개를 넘지 않게 시작하세요.

페이지목적들어갈 내용
홈(index.html)첫인상과 이동 안내한 줄 소개, 대표 이미지, 주요 메뉴
소개(about.html)누구인지 설명소개 글, 사진, 경험
활동(projects.html)결과물 보여 주기카드 3~6개, 링크
연락처(contact.html)연락 방법 안내이메일, 폼, 운영 시간
404.html (선택)없는 주소 안내“페이지를 찾을 수 없습니다”, 홈 링크

각 페이지에는 h1을 하나만 두고, 메뉴 이름과 페이지 제목을 가능하면 같게 맞춥니다. 그래야 방문자가 현재 위치를 이해하기 쉽습니다.

3. 종이에 화면 스케치하기

디자인 도구를 배우기 전에 네모와 선으로 충분합니다. 머리글, 메뉴, 본문, 바닥글의 위치만 정해도 절반은 끝난 것입니다.

스케치 예시 
┌──────────────────────────────┐
│ 로고            홈 소개 연락 │
├──────────────────────────────┤
│                              │
│   안녕하세요, 사피엔스입니다 │
│   [활동 보기]                │
│                              │
├──────────────────────────────┤
│ 소개   활동   연락처         │
├──────────────────────────────┤
│ © 2026 사피엔스              │
└──────────────────────────────┘

모바일 스케치도 한 장 그려 봅니다. 좁은 화면에서는 메뉴가 아래로 접히거나, 카드가 한 열로 쌓이는 모습을 미리 생각해 둡니다.

4. 폴더와 파일 구조 만들기

파일 이름은 소문자·숫자·하이픈으로 짓고, 공백이나 한글은 피합니다. GitHub Pages는 대소문자를 구분하므로 About.html과 about.html은 다른 파일입니다.

권장 구조 
my-site/
├── index.html
├── about.html
├── projects.html
├── contact.html
├── 404.html
└── assets/
    ├── css/
    │   └── style.css
    ├── js/
    │   └── main.js
    └── images/
        ├── profile.jpg
        └── project-01.jpg

이 사이트처럼 assets/style.css와 assets/common.js를 바로 두어도 됩니다. 중요한 것은 한 가지 규칙을 정하고 모든 페이지에서 똑같이 쓰는 것입니다.

주의

이미지 파일명에 공백이나 한글이 들어가면 링크가 깨지기 쉽습니다. profile.jpg, project-01.jpg처럼 영문 소문자와 하이픈을 사용하세요.

5. 글과 이미지 준비하기

디자인보다 내용이 먼저입니다. 각 페이지에 들어갈 글을 메모장에 먼저 쓰고, 그다음 필요한 이미지를 고릅니다.

  • 직접 찍거나 만든 이미지를 우선 사용합니다. 인터넷 이미지는 출처와 이용 허락을 확인합니다.
  • 큰 사진은 가로 1600px 안팎으로 줄이고, JPEG·WebP 형식을 사용합니다.
  • 이미지에는 항상 alt 설명을 붙입니다. 장식용 이미지라면 빈 alt=""도 가능합니다.
  • 사진 아래에 설명이 필요하면 figure와 figcaption을 사용합니다.
준비물권장 기준확인할 점
대표 이미지가로 1200~1600px홈에서 가장 먼저 보이는가
프로필 사진정사각형 400~800px얼굴이 잘리지 않는가
글한 문단 2~4문장휴대폰에서 읽기 편한가
연락 정보공개해도 되는 값개인정보가 과하게 노출되지 않는가

6. 처음부터 챙길 기본 규칙

  • <html lang="ko">로 문서 언어를 알려 줍니다.
  • 모든 페이지에 서로 다른 <title>과 한 줄 설명(meta description)을 넣습니다.
  • 링크는 색만으로 구분하지 말고 밑줄이나 아이콘을 함께 사용합니다.
  • 버튼과 링크는 키보드 Tab으로 이동할 수 있어야 합니다.
  • 글자와 배경의 대비를 충분히 주고, 본문 글자는 최소 16px 안팎으로 시작합니다.
  • 폼 입력에는 반드시 연결된 label을 붙입니다.
TIP

기획 단계에서 이 규칙을 정해 두면, 나중에 페이지를 추가할 때마다 같은 품질을 유지하기 쉽습니다.

7. 기획서 한 장으로 정리하기

아래 항목을 메모장에 채우면 기획이 끝납니다. 이 메모는 작업 중간에 다시 확인하는 기준이 됩니다.

항목예시
사이트 이름사피엔스 동아리
한 줄 소개배움과 기록을 나누는 동아리
대상신입 부원, 외부 방문자
페이지홈, 소개, 활동, 연락처
색과 글꼴파란색 계열, 시스템 글꼴
이미지프로필 1장, 활동 사진 3장
완료 기준휴대폰 메뉴, 연락처 링크, 콘솔 오류 없음

완료 체크리스트

  • 사이트의 목표와 대상을 한 문장으로 적었다.
  • 첫 버전에 넣을 페이지와 넣지 않을 기능을 정했다.
  • 홈·소개·연락처 등 페이지 역할을 표로 정리했다.
  • 데스크톱과 모바일 화면을 종이에 스케치했다.
  • 폴더 구조와 파일 이름 규칙을 정했다.
  • 글과 이미지, 접근성 기본 규칙을 확인했다.
