WEB MAKING

웹제작

이 안내를 위에서부터 따라 하면 VS Code에서 자기소개 웹사이트를 만들고 GitHub Pages에 공개할 수 있습니다. 각 단계의 예제를 빠짐없이 복사하고, 파일 이름과 저장소 설정을 그대로 맞춰주세요.

학습 진행: 0 / 10 단계

완성 결과: 버튼을 누르면 인사말이 나타나는 반응형 웹사이트가 인터넷 주소로 공개됩니다. GitHub Pages는 HTML·CSS·JavaScript 정적 웹사이트용이며, 로그인·데이터베이스·Java/Python 서버는 이 안내의 배포 대상이 아닙니다.

준비저장소 만들기VS Code 연결파일 만들기로컬 확인GitHub 업로드Pages 배포주소 확인수정·재배포문제 해결

1단계. 준비물 설치 및 확인

  1. GitHub 계정이 없으면 GitHub 가입 페이지에서 계정을 만들고 이메일 인증을 마칩니다. 기존 계정이 있으면 로그인합니다.
  2. Visual Studio Code를 설치합니다.
  3. Git for Windows를 설치합니다. 설치 중 별도 변경이 필요하지 않으면 기본 선택값을 그대로 사용해도 됩니다.
  4. VS Code를 열고 위쪽 메뉴에서 Terminal → New Terminal을 누릅니다. 터미널에 git --version을 입력하고 Enter를 누릅니다. git version 2...처럼 버전이 출력되면 준비된 것입니다.

“git을 찾을 수 없습니다”라는 오류가 나오면 Git 설치를 마친 뒤 VS Code를 완전히 닫았다 다시 열어 확인합니다.

2단계. GitHub에 새 저장소 만들기

  1. GitHub에 로그인한 다음 오른쪽 위 + 버튼을 누르고 New repository를 선택합니다.
  2. Repository name에 first-website-practice를 입력합니다. 이 이름은 사이트 주소에도 포함되므로 영문 소문자와 하이픈을 권장합니다.
  3. Description은 비워도 됩니다. Public을 선택합니다. GitHub Free에서 공개 저장소로 Pages를 사용할 수 있습니다.
  4. Add a README file을 체크합니다. README가 기본 main 브랜치를 만들어 이후 업로드가 쉬워집니다.
  5. Add .gitignore와 Choose a license는 처음에는 None 그대로 둡니다. Create repository를 누릅니다.

저장소 화면이 열리고 first-website-practice라는 제목과 README 파일이 보이면 성공입니다. 이 실습 저장소는 공개되므로 비밀번호, API 키, 주소·전화번호 등 공개하면 안 되는 정보를 올리지 마세요.

3단계. 저장소를 VS Code로 복사하기(Clone)

  1. GitHub 저장소 페이지에서 초록색 Code 버튼을 누르고 HTTPS 탭의 주소 복사 버튼을 누릅니다. 주소는 https://github.com/내GitHub이름/first-website-practice.git 형태입니다. 여기서 “내GitHub이름”은 실제 계정 이름으로 표시됩니다.
  2. VS Code로 돌아옵니다. Ctrl+Shift+P를 눌러 명령 팔레트를 열고 Git: Clone을 입력해 선택합니다.
  3. 복사한 HTTPS 주소를 붙여넣고 Enter를 누릅니다.
  4. 폴더 선택 창이 나오면 프로젝트를 저장할 위치(예: 문서)를 고르고 Select as Repository Destination을 누릅니다. 기존 작업 파일이 없는 위치를 선택하세요.
  5. 복사가 끝나면 Open을 눌러 저장소 폴더를 VS Code에서 엽니다. GitHub 로그인을 요청하면 브라우저 창에서 승인합니다.

VS Code의 Explorer 맨 위에 FIRST-WEBSITE-PRACTICE 폴더와 README.md가 보이면 올바른 폴더를 연 것입니다. 다음 파일들은 이 폴더의 맨 위(root)에 만듭니다.

4단계. 웹사이트 파일 3개 만들고 예제 붙여넣기

VS Code 왼쪽 Explorer 위의 New File 아이콘을 눌러 아래 파일을 하나씩 만듭니다. 이름을 정확히 입력하세요. .txt가 뒤에 붙거나 파일을 하위 폴더 안에 만들면 사이트에서 찾지 못합니다.

  • index.html — 웹페이지 내용
  • style.css — 색상과 배치
  • script.js — 버튼 동작

각 파일을 클릭해 아래 코드 블록의 내용을 처음부터 끝까지 해당 파일에 붙여넣고 Ctrl+S를 눌러 저장합니다. 복사할 때 코드 블록의 설명이나 이 페이지의 글은 포함하지 않습니다.

index.html에 붙여넣을 전체 내용

<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>나의 첫 웹사이트</title>
  <link rel="stylesheet" href="style.css">
  <script src="script.js" defer></script>
</head>
<body>

    <p class="eyebrow">MY FIRST WEBSITE</p>
    <h1>안녕하세요!</h1>

    <button id="hello-button" type="button">인사 받기</button>

  </main>
</body>
</html>

button.addEventListener("click", () => {
  message.textContent = "방문해주셔서 감사합니다!";
});

Explorer에서 파일 세 개가 README와 같은 들여쓰기 수준에 보여야 합니다. 탭 제목의 흰색 점은 저장되지 않은 변경이 있다는 뜻이므로, 저장한 뒤 점이 사라졌는지 확인하세요.

5단계. 내 컴퓨터에서 먼저 실행하기

  1. Explorer에서 index.html을 마우스 오른쪽 버튼으로 누르고 Reveal in File Explorer(파일 탐색기에 표시)를 선택합니다.
  2. 열린 Windows 폴더에서 index.html을 더블 클릭합니다. 또는 VS Code 확장 탭에서 Live Server를 검색해 설치한 뒤 파일을 오른쪽 클릭하고 Open with Live Server를 선택합니다.
  3. 브라우저에 “안녕하세요!” 제목과 “인사 받기” 버튼이 보이는지 확인합니다. 버튼을 눌렀을 때 감사 문구가 나타나면 세 파일 연결이 성공한 것입니다.
  4. 화면이 다르거나 버튼이 동작하지 않으면 파일 이름과 4단계 예제를 다시 확인하고 저장한 뒤 브라우저를 새로고침합니다.

6단계. GitHub에 파일 업로드(Push)

저장소를 Clone했기 때문에 원격 저장소 연결은 이미 되어 있습니다. 새 저장소를 다시 만들거나 git remote add를 실행하지 마세요. VS Code 메뉴에서 Terminal → New Terminal을 누르고, 터미널 경로 끝에 first-website-practice가 표시되는지 확인합니다.

아래 명령을 한 줄씩 붙여넣고 매번 Enter를 누릅니다.

git status
git add index.html style.css script.js
git commit -m "Create my first website"
git push

git status에서 세 파일이 변경 파일로 보이는 것이 정상입니다. 커밋 성공 후 git push도 오류 없이 끝나면 GitHub 저장소 페이지를 새로고침해 세 파일이 올라왔는지 확인합니다.

“Author identity unknown” 오류가 날 때만 아래 두 줄에 본인 이름과 GitHub 가입 이메일을 넣고 실행한 뒤, 위의 네 명령을 다시 실행합니다.

git config --global user.name "본인 이름"
git config --global user.email "GitHub 가입 이메일"

로그인 창이나 권한 승인 창이 나오면 같은 GitHub 계정으로 로그인하고 승인합니다. 비밀번호나 토큰을 코드 파일에 적거나 다른 사람과 공유할 필요는 없습니다.

7단계. GitHub Pages 켜기

  1. GitHub에서 first-website-practice 저장소를 열고 상단의 Settings 탭을 누릅니다. 탭이 안 보이면 저장소 안에 있는지 확인합니다.
  2. 왼쪽 메뉴의 Pages를 선택합니다. 메뉴가 바로 안 보이면 설정 페이지의 왼쪽 목록을 아래로 내려 찾습니다.
  3. Build and deployment 아래 Source를 Deploy from a branch로 선택합니다.
  4. Branch를 main, 폴더를 /(root)로 고른 다음 Save를 누릅니다.
  5. Actions 탭을 열어 Pages 작업이 진행되는지 봅니다. 노란색 진행 표시가 초록색 성공 표시로 바뀔 때까지 기다립니다. 첫 게시에는 몇 분 걸릴 수 있습니다.

저장소에 로그인 기능이나 데이터베이스 연결이 있다면 공개 저장소에 비밀번호, API 키, 개인 정보를 올리지 마세요. 이 실습은 브라우저에서 실행되는 정적 사이트만 게시합니다.

8단계. 공개된 웹사이트 주소 열기

Settings → Pages 화면의 상단에 Your site is live at라는 문구와 주소가 나타나면 그 주소를 누릅니다. 주소는 다음 모양입니다.

https://내GitHub이름.github.io/first-website-practice/

내GitHub이름 부분은 본인의 실제 GitHub 사용자 이름으로 바뀝니다. GitHub 사용자 이름과 저장소 이름을 그대로 확인해 주소에 오타가 없는지 살펴보세요.

웹사이트가 열리고 버튼도 작동하면 누구나 접속할 수 있도록 게시된 것입니다. 바로 안 열리면 2~5분 기다린 뒤 새로고침합니다. 브라우저에서 Ctrl+F5를 누르면 이전 화면 대신 최신 파일을 다시 불러올 수 있습니다.

9단계. 내용을 수정하고 다시 게시하기

VS Code에서 index.html의 “안녕하세요!”를 원하는 문구로 바꾸고 저장합니다. 로컬 브라우저에서 먼저 확인한 다음 VS Code 터미널에서 아래를 실행합니다.

git add index.html style.css script.js
git commit -m "Update my website"
git push

GitHub 저장소의 Actions 탭에서 새 배포가 성공하면 같은 사이트 주소를 새로고침합니다. Pages 설정을 다시 할 필요는 없습니다.

10단계. 자주 생기는 문제 해결

  • 주소에서 404가 나옵니다: 저장소가 Public인지 확인하고, Settings → Pages가 main과 /(root)인지 확인합니다. 저장소 맨 위에 index.html이 있어야 합니다.
  • Actions가 실패합니다: Actions 탭에서 실패한 작업을 열어 빨간 오류를 확인합니다. 코드 파일은 저장소 루트에 두고 파일 이름의 철자를 맞춥니다.
  • 페이지는 열리는데 디자인이 없습니다: 파일명이 style.css인지, HTML에 href="style.css"가 있는지 확인합니다.
  • 버튼이 작동하지 않습니다: 파일명이 script.js인지, HTML에 src="script.js"가 있는지 확인합니다. 개발자 도구는 브라우저에서 F12를 누른 뒤 Console 탭을 확인합니다.
  • 수정한 화면이 안 보입니다: GitHub 저장소에 새 수정이 올라갔는지, Actions의 배포가 초록색 성공인지 확인한 뒤 Ctrl+F5를 누릅니다.
  • “nothing to commit”이 나옵니다: 파일을 저장했는지, VS Code 터미널이 Clone한 저장소 폴더인지 확인합니다. git status가 변경 파일을 보여주는지 확인합니다.

GitHub Pages는 공개 웹사이트를 만드는 서비스입니다. 방문자가 입력한 내용을 여러 사람에게 저장·공유하거나 회원 로그인을 처리하려면 서버와 데이터베이스를 별도로 공부해야 합니다.

완료 체크는 현재 브라우저에만 저장됩니다.
