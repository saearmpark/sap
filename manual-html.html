웹제작절차 03

HTML 제작

HTML은 웹 페이지의 뼈대입니다. 제목, 문단, 목록, 링크, 이미지, 입력 폼을 배치하고 CSS·JavaScript가 붙을 수 있는 자리를 만듭니다. 이 단계에서는 새 페이지 한 장을 직접 만들어 봅니다.

난이도 · 입문 예상 시간 · 25분 준비물 · VS Code

1. HTML 파일의 기본 구조

프로젝트 폴더에 practice.html을 만들고 아래 내용을 그대로 입력합니다. 파일명은 소문자와 하이픈을 쓰는 것이 안전합니다.

practice.html 
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>나의 첫 페이지</title>
</head>
<body>
  <h1>안녕하세요</h1>
  <p>처음 만든 웹 페이지입니다.</p>
</body>
</html>
부분역할
<!DOCTYPE html>최신 HTML 문서임을 알려 줍니다.
<head>화면에 직접 보이지 않는 설정(제목, 인코딩, 스타일 링크)을 담습니다.
<meta charset="UTF-8">한글이 깨지지 않게 합니다.
<body>실제로 화면에 보이는 내용을 담습니다.

2. 글과 목록

HTML 
<h1>사이트 제목</h1>
<h2>큰 소제목</h2>
<h3>작은 소제목</h3>

<p>문단입니다. <strong>중요한 말</strong>은 굵게,
<em>강조할 말</em>은 기울임으로 표시합니다.</p>

<ul>
  <li>순서가 없는 항목</li>
  <li>두 번째 항목</li>
</ul>

<ol>
  <li>첫 번째 단계</li>
  <li>두 번째 단계</li>
</ol>

h1은 페이지에 하나만 두는 것이 좋습니다. 제목 단계를 건너뛰지 말고 h1 → h2 → h3 순서로 사용하세요.

3. 링크와 이미지

HTML 
<!-- 같은 폴더의 페이지로 이동 -->
<a href="manual.html">웹제작절차 목차</a>

<!-- 새 탭에서 외부 사이트 열기 -->
<a href="https://example.com" target="_blank" rel="noopener">예시 사이트</a>

<!-- 같은 폴더 images 폴더의 사진 -->
<img src="images/photo.jpg" alt="해변에서 찍은 단체 사진"
     width="640" height="427" loading="lazy">
중요

alt는 이미지가 안 보일 때 대신 읽히는 설명입니다. 화면 낭독기 사용자에게도 필요하므로 반드시 적습니다. 링크 주소는 대소문자까지 정확히 맞춰야 합니다.

이미지는 images 폴더에 넣고, 파일명은 photo.jpg처럼 영문 소문자와 하이픈으로 짓습니다. width와 height를 적으면 이미지가 늦게 로드되어도 화면이 덜 흔들리고, loading="lazy"는 아래쪽 이미지를 필요할 때 불러옵니다.

4. 의미 있는 구조 태그

페이지를 div로만 나누기보다 역할이 드러나는 태그를 사용하면 CSS와 검색 엔진, 화면 낭독기가 모두 이해하기 쉬워집니다.

HTML 
<body>
  <header>
    <h1>사피엔스</h1>
    <p>배움과 기록을 위한 공간</p>
  </header>

  <nav aria-label="주요 메뉴">
    <a href="index.html">홈</a>
    <a href="manual.html">웹제작절차</a>
  </nav>

  <main>
    <section>
      <h2>소개</h2>
      <p>본문 내용</p>
    </section>
  </main>

  <footer>
    <p>© 2026 사피엔스</p>
  </footer>
</body>

5. class와 id

CSS와 JavaScript가 특정 요소를 찾을 수 있도록 이름표를 붙입니다. class는 여러 번, id는 페이지 안에서 한 번만 쓰는 것이 원칙입니다.

HTML 
<p class="note">여러 곳에서 재사용하는 설명</p>
<button id="save-button" type="button">저장</button>

<!-- 이름 규칙 예시: 소문자 + 하이픈 -->
<div class="manual-callout is-tip">...</div>

6. 입력 폼

사용자에게 글을 받으려면 form과 input을 사용합니다. 모든 입력에는 연결된 label이 있어야 합니다.

HTML 
<form id="contact-form">
  <label for="name">이름</label>
  <input id="name" name="name" type="text" required>

  <label for="email">이메일</label>
  <input id="email" name="email" type="email" required>

  <label for="message">내용</label>
  <textarea id="message" name="message" rows="4"></textarea>

  <button type="submit">보내기</button>
</form>

type="email", required 같은 속성은 브라우저가 기본 검사를 해 줍니다. JavaScript 검증은 그 위에 추가하는 것입니다.

7. 이 사이트에 새 페이지 추가하기

이 저장소의 페이지는 공용 사이드바와 테마를 불러오는 골격을 사용합니다. 새 파일을 루트에 만들고 아래처럼 시작하면 메뉴와 다크 모드가 자동으로 적용됩니다.

my-page.html 
<!DOCTYPE html>
<html lang="ko">
<head>
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<meta name="theme-color" content="#202124">
<link rel="icon" href="assets/icons/icon-192.png" type="image/png">
<link rel="apple-touch-icon" href="assets/icons/apple-touch-icon.png">
<link rel="manifest" href="manifest.webmanifest">
<title>사피엔스 — 새 페이지</title>
<script>try { if (localStorage.getItem("sap-theme") === "dark") document.documentElement.dataset.theme = "dark"; } catch {}</script>
<link rel="stylesheet" href="assets/style.css?v=labels-43">
</head>
<body>
<div class="layout">
  <aside class="sidebar">
    <nav class="nav-group" data-nav></nav>
  </aside>
  <main class="main">
    <div class="eyebrow">NEW</div>
    <h1>새 페이지</h1>
    <p>내용을 작성합니다.</p>
  </main>
</div>
<script src="assets/common.js?v=labels-43"></script>
<script src="assets/auth.js?v=labels-43"></script>
<script src="assets/theme.js?v=labels-43"></script>
</body>
</html>

그다음 assets/common.js의 메뉴 목록에 링크를 추가하고, .github/scripts/pages.txt와 search.html, sw.js의 CORE에도 등록해야 합니다. 자세한 절차는 07 · 제작항목 연결에서 다룹니다.

TIP

theme-color, 아이콘, manifest.webmanifest는 홈 화면 설치와 오프라인 동작에 필요합니다. 이 네 줄을 빼면 페이지는 열리지만 PWA로 인식되지 않습니다.

8. 확인과 디버깅

  • 브라우저에서 F12를 눌러 Elements 탭을 열면 실제 DOM 구조를 볼 수 있습니다.
  • Console 탭에 빨간 오류가 있으면 파일 경로나 문법을 먼저 확인합니다.
  • 태그를 열었으면 반드시 닫습니다. 닫는 태그가 빠지면 뒤쪽 내용이 엉뚱한 곳에 들어갑니다.
  • 들여쓰기는 동작에 영향이 없지만, 오류를 찾기 쉽게 하기 위해 단계마다 맞춰 줍니다.
TIP

처음부터 완벽하게 만들 필요는 없습니다. 글을 먼저 넣고, 브라우저에서 확인하고, 다음에 디자인을 입히는 순서가 빠릅니다.

9. 메타 정보와 접근성

검색 결과와 브라우저 탭에 보이는 정보를 채우고, 키보드와 화면 낭독기 사용자도 이용할 수 있게 만듭니다. 이 저장소의 페이지도 같은 원칙을 따릅니다.

HTML 
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <meta name="description" content="사피엔스 동아리의 소개와 활동을 정리한 페이지입니다.">
  <title>사피엔스 동아리 — 소개</title>
</head>

<figure>
  <img src="images/photo.jpg" alt="해변에서 찍은 단체 사진"
       width="640" height="427" loading="lazy">
  <figcaption>2026년 봄 활동 사진</figcaption>
</figure>
  • 페이지마다 title을 다르게 쓰고, description은 한두 문장으로 요약합니다.
  • 이미지의 alt, 폼의 label, 제목 순서(h1 → h2 → h3)를 확인합니다.
  • 링크 글자는 “여기”보다 “활동 사진 보기”처럼 목적지가 드러나게 씁니다.
  • 색만으로 정보를 구분하지 말고 밑줄·아이콘·문구를 함께 사용합니다.
  • 키보드 Tab으로 모든 메뉴와 버튼에 접근되는지 확인합니다.

완료 체크리스트

  • practice.html을 만들고 Live Server로 열었다.
  • 제목·문단·목록·링크·이미지를 각각 하나 이상 넣었다.
  • header, main, section, footer로 구조를 나눴다.
  • 입력 폼에 label을 연결했다.
  • 페이지마다 title과 description을 넣었다.
  • 이미지에 alt, width, height, loading을 적용했다.
  • 공용 사이드바를 불러오는 페이지 골격을 이해했다.
