# codestudio 게임제작 실습 (Python)

game.html의 "게임제작" 메뉴에 있는 STEP과 같은 순서로, 같은 게임을 Python(pygame-ce)으로
직접 만들어보는 폴더입니다.

## 실행 방법

```bash
cd games/python
pip install -r requirements.txt
python tictactoe_pygame.py
```

- 클릭: 칸에 O/X 놓기
- `R` 키: 다시 시작
- 창 닫기: 종료

## 학습 포인트 (STEP 1: 틱택토)

- **게임 루프**: `while True:` 안에서 이벤트 처리 → 화면 그리기 → `clock.tick()`으로 속도 제한, 이 세 가지가
  거의 모든 게임의 기본 구조입니다. `game.html`의 JS 버전은 클릭할 때마다 다시 그리는 방식이라 별도 루프가
  없다는 차이도 비교해보세요.
- **좌표 → 칸 번호 변환**: 마우스 클릭 좌표(`x, y`)를 `CELL_SIZE`로 나눠 몇 번째 칸인지 계산하는 부분
  (`col, row = x // CELL_SIZE, y // CELL_SIZE`)이 이후 모든 게임에서 반복해서 쓰이는 패턴입니다.
- **승리 조건 판별**: 가로/세로/대각선 8가지 경우의 수를 리스트(`WIN_LINES`)로 미리 정의해두고 순회하는 방식은
  JS 버전과 동일한 로직입니다.

## STEP 2: 벽돌깨기

```bash
python breakout_pygame.py
```

- 마우스 또는 좌우 방향키: 패들 이동
- `R` 키: 다시 시작

학습 포인트:

- **매 프레임 갱신**: 틱택토는 클릭할 때만 화면이 바뀌지만, 벽돌깨기는 `clock.tick(60)`으로 초당 60번
  공 위치를 갱신하고 다시 그립니다. 이게 진짜 "게임 루프"입니다.
- **충돌 처리**: `pygame.Rect.colliderect()`로 공과 패들/벽돌이 겹쳤는지 검사하고, 겹치면 공의 방향(`dy`)을 뒤집습니다.
- **각도 조절**: 패들의 어느 위치에 맞았는지(`hit`)에 따라 좌우 방향(`dx`)을 바꿔서 조작감을 만듭니다.

## STEP 3: 슈팅게임

```bash
python shooter_pygame.py
```

- 좌우 방향키: 이동 · 스페이스바: 발사 · `R` 키: 다시 시작

학습 포인트:

- **여러 개체 관리**: 벽돌깨기는 공 하나만 다뤘지만, 슈팅게임은 총알과 적이 동시에 여러 개 존재합니다.
  각각을 리스트(`bullets`, `enemies`)로 관리하고, 매 프레임 화면 밖으로 나간 것과 맞은 것을 걸러내는
  (`[x for x in items if 조건]`) 패턴이 핵심입니다.
- **난이도를 시간에 따라 조절**: `elapsed`(경과 프레임)가 늘어날수록 적이 더 자주, 더 빠르게 등장하도록
  `spawn_interval()`과 `enemy_speed()` 함수로 계산합니다.
- **충돌을 한 번에 정리하기**: 총알-적 충돌을 먼저 모두 찾아 표시해두고, 그다음에 한 번에 걸러내는 방식으로
  "루프를 도는 중에 리스트를 바꾸면 생기는 버그"를 피합니다.

## STEP 4: 슬라이딩 퍼즐

```bash
python puzzle_pygame.py
```

- 마우스 클릭: 빈칸과 붙어있는 칸 이동
- `R`: 섞기 · `S`: 저장 · `L`: 불러오기

학습 포인트:

- **JSON으로 상태 저장/불러오기**: `save()`는 `json.dump()`로 리스트를 `puzzle_save.json` 파일에 그대로 저장하고,
  `load()`는 `json.load()`로 다시 읽어옵니다. STEP 2(할일 관리)가 직접 만든 텍스트 형식(`0|내용`)을 썼다면,
  이번엔 JSON이라는 표준 형식을 씁니다. `game.html`의 JS 버전은 파일 대신 브라우저의 `localStorage`를 쓴다는
  차이도 비교해보세요.
- **항상 풀 수 있는 상태로 섞기**: 숫자를 완전히 무작위로 섞으면 절반은 이론적으로 풀 수 없는 배치가 됩니다.
  그래서 "빈칸과 인접한 칸만 반복해서 바꾸는" 방식으로 섞어, 항상 풀 수 있는 상태를 보장합니다.
- **좌표 계산 재사용**: STEP 1(틱택토)에서 썼던 "클릭 좌표 → 칸 번호" 계산이 여기서도 그대로 쓰입니다.

## STEP 5: 스네이크

```bash
python snake_pygame.py
```

- 방향키: 이동 · `R` 키: 다시 시작

학습 포인트:

- **그리는 빈도와 움직이는 빈도를 분리하기**: 화면은 `clock.tick(60)`으로 초당 60번 그리지만, 뱀은
  `MOVE_INTERVAL_MS`(120밀리초)마다 한 칸씩만 움직입니다. `move_timer`에 경과 시간(`dt`)을 계속 더하다가
  간격을 넘으면 한 번만 이동시키는 방식으로, "그리기"와 "게임 로직"의 속도를 서로 다르게 관리하는 법을 배웁니다.
- **몸이 길어지는 자료구조**: 뱀의 몸은 좌표 튜플의 리스트(`snake`)이고, 맨 앞(인덱스 0)이 머리입니다.
  이동할 때는 새 머리를 앞에 추가(`insert(0, ...)`)하고, 사과를 못 먹었으면 꼬리를 하나 제거(`pop()`)해서
  길이를 유지합니다. 사과를 먹었을 때는 꼬리를 제거하지 않아서 몸이 한 칸 길어집니다.
- **반대 방향 전환 막기**: 오른쪽으로 가는 중에 왼쪽 키를 누르면 즉시 자기 몸으로 들어가 버리므로,
  새 방향이 현재 방향의 정반대일 때는 무시합니다.

## STEP 6: 테트리스

```bash
python tetris_pygame.py
```

- 좌우 방향키: 이동(누르고 있으면 빠르게 연속 이동) · 위 방향키: 회전 · 아래 방향키: 빨리 내리기 ·
  스페이스바: 바로 떨어뜨리기 · Shift: 홀드 · `R`: 다시 시작

학습 포인트:

- **2차원 배열로 보드와 블록 표현하기**: 쌓인 블록은 `grid`(20행 × 10열 리스트), 떨어지는 블록은
  0/1로 채운 작은 2차원 리스트(`matrix`)로 표현합니다. 두 배열을 겹쳐서 충돌을 검사하고(`collide()`),
  바닥에 닿으면 `merge()`로 `grid`에 합칩니다.
- **회전을 한 줄로 구현하기**: `rotate()` 함수의 `list(zip(*matrix[::-1]))`는 "행렬을 뒤집고 전치한다"는
  뜻으로, 2차원 리스트를 시계 방향으로 90도 돌리는 일반적인 방법입니다. 블록마다 따로 회전 모양을
  만들어두지 않고 이 한 함수로 7가지 블록을 전부 회전시킵니다.
- **벽 차기(wall kick)**: 회전했을 때 벽이나 다른 블록에 부딪히면 바로 포기하지 않고, 좌우로 한두 칸
  밀어서(`offset`) 다시 검사합니다. 실제 테트리스도 이런 보정을 거쳐야 좁은 틈에서도 회전이 됩니다.
- **줄 삭제와 당겨오기**: 가로 한 줄이 전부 채워지면(`all(grid[r])`) 그 줄을 삭제(`del`)하고 맨 위에
  빈 줄을 하나 추가(`insert(0, ...)`)합니다. 그러면 위에 있던 블록들이 자연스럽게 한 칸씩 내려오는
  효과가 납니다.
- **STEP 5와 같은 "그리기 vs 로직" 속도 분리**: 화면은 `clock.tick(60)`으로 매끄럽게 그리지만, 블록은
  `DROP_INTERVAL_MS`(500밀리초)마다 한 칸씩만 자동으로 내려옵니다.
- **미리 한 칸 준비해두기(NEXT)**: 다음에 나올 블록의 종류를 `next_type`에 미리 뽑아두고, 새 블록이
  필요할 때(`spawn()`) 그걸 꺼내 쓰면서 또 다른 블록을 새로 뽑습니다. 화면에는 이 값을 그대로
  작게 그려서 미리보기로 보여줍니다.
- **홀드(HOLD)**: 지금 블록을 보관해두고 다음 블록(또는 이미 보관해둔 블록)으로 바꿔 끼우는 기능입니다.
  `hold_used` 플래그로 "이번 블록에서 이미 홀드를 썼는지"를 기억해서, 블록 하나당 한 번만 쓸 수 있게
  제한합니다 — 이 제한이 없으면 홀드만 계속 눌러서 원하는 블록이 나올 때까지 무한히 뽑을 수 있게 됩니다.
- **그림자(고스트) 블록**: 지금 블록을 그대로 두면 어디에 떨어질지, `ghost_row()`로 "바닥이나 다른
  블록에 닿기 직전까지" 미리 계산해서 반투명하게 그립니다. 하드 드롭(`hard_drop()`)도 내부적으로
  같은 함수로 위치를 구합니다.
- **DAS(Delayed Auto Shift)**: 방향키를 누르는 순간 한 칸만 움직이고, 일정 시간(`DAS_DELAY_MS`)이
  지나도록 계속 누르고 있으면 그 다음부터는 훨씬 짧은 간격(`DAS_SPEED_MS`)으로 계속 움직입니다.
  "누른 순간"과 "누르고 있는 동안"을 구분해서 처리하는 것이 핵심입니다.

## STEP 7: 2048

```bash
python 2048_pygame.py
```

- 방향키: 밀기 · `R` 키: 다시 시작

학습 포인트:

- **지금까지와 다른 종류의 게임**: STEP 1~6은 모두 "블록이나 공이 떨어지는" 게임이었지만, 2048은
  키를 한 번 누르면 4×4 격자 전체가 그 방향으로 한꺼번에 밀리는 방식입니다. 그래서 매 프레임
  갱신하는 게임 루프 대신, "키 입력 한 번 → 격자 변환 한 번"이 핵심 구조입니다.
- **한 줄을 압축하고 병합하기**: `slide_row_left()`가 이 게임의 핵심입니다. 빈 칸(0)을 걷어내고
  (`filtered`), 그다음 왼쪽부터 순서대로 보면서 같은 값이 연속으로 나오면 한 번만 합칩니다.
  합쳐진 칸은 건너뛰어야(`i += 2`) "세 칸이 연속으로 같을 때 한 번에 다 합쳐지는" 버그를 막을 수 있습니다.
- **네 방향을 하나의 함수로 처리하기**: 왼쪽으로 미는 로직(`slide_row_left`)만 만들어두고, 다른
  세 방향은 격자를 미리 돌려놓았다가(`transpose`, `reverse_rows`) 같은 함수를 적용한 뒤 다시
  원래대로 돌려놓는 방식(`transform_in`/`transform_out`)으로 처리합니다. STEP 6(테트리스)의
  `rotate()`와 같은 "행렬 변환"의 또 다른 활용 예시입니다.
- **움직였을 때만 새 타일 생성**: 눌렀는데 그 방향으로 아무것도 바뀌지 않았다면(벽에 막혀 있거나
  합쳐질 것이 없을 때) 새 타일을 만들지 않습니다. `moved` 플래그로 "실제로 격자가 바뀌었는지"를
  구분하는 것이 중요합니다.
- **게임 오버 판정**: 빈 칸이 없어도 네 방향 중 하나라도 밀어서 합쳐질 수 있으면 아직 게임 오버가
  아닙니다. `has_moves_left()`는 네 방향을 전부 시뮬레이션해보고 하나도 움직이지 않을 때만
  게임 오버로 처리합니다.

## STEP 8: 두더지 잡기

```bash
python whackamole_pygame.py
```

- 마우스 클릭: 두더지 잡기 (웹 버전에서는 화면 탭) · `R` 키: 다시 시작

학습 포인트:

- **키보드 없이 포인터(클릭/탭)만으로 조작하기**: STEP 1~7은 전부 방향키 등 키보드를 썼지만, 이 게임은
  `MOUSEBUTTONDOWN` 이벤트의 좌표(`event.pos`)를 어느 구멍인지로 변환(`col, row = mx // CELL, my // CELL`)
  하는 것이 전부입니다. 같은 방식이 웹 버전에서는 마우스 클릭과 터치 탭을 모두 `click` 이벤트 하나로
  처리할 수 있게 해줘서, 별도 코드 없이 휴대폰에서도 그대로 동작합니다.
- **여러 타이머를 동시에 관리하기**: 구멍이 9개이므로 "몇 번 구멍에 두더지가 언제까지 올라와 있는지"를
  구멍마다 따로 기억해야 합니다. 이 코드에서는 리스트(`up_until`)에 "몇 시(밀리초)까지 올라와 있을지"를
  저장해두고, 매 프레임 지금 시각과 비교하는 방식으로 단순화했습니다. 테트리스의 `setInterval` 하나와
  달리, 이번엔 "여러 개의 독립적인 시계"를 다뤄야 한다는 점이 다릅니다.
- **시간에 따른 난이도 조절**: STEP 3(슈팅게임)에서 썼던 패턴과 같습니다 — 경과 시간(`elapsed`)이
  늘어날수록 두더지가 더 짧게 보이고(`mole_visible_ms`) 더 자주 나타나도록(`spawn_interval_ms`)
  계산해서, 게임이 진행될수록 자연스럽게 어려워집니다.

줄 삭제, 격자 압축/병합, 포인터 기반 조작까지 게임 개발의 기본기를 한 바퀴 돈 것입니다. 다음은
나만의 게임 아이디어로 확장해보세요.
