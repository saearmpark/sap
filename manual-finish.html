첫 웹사이트 완성

앞에서 배운 기획·HTML·CSS·JavaScript·배포를 한 번에 연결해 1페이지 포트폴리오를 완성합니다. 코드를 그대로 따라 한 뒤 내 문구와 사진으로 바꾸면 첫 웹사이트가 됩니다.

난이도 · 초급 예상 시간 · 40분 준비물 · VS Code, 웹 브라우저, GitHub 계정

1. 완성할 사이트

한 페이지 안에 소개, 프로젝트, 연락 폼을 담고, 메뉴를 누르면 해당 위치로 이동하는 사이트를 만듭니다. 페이지를 여러 장으로 나누는 방법은 07단계에서 다룹니다.

머리글·메뉴 → 소개 → 프로젝트 → 연락 폼 → 바닥글

완성 후에는 GitHub Pages에 올려 주소로 접속할 수 있게 합니다. 로그인이나 결제는 넣지 않습니다.

2. 폴더와 파일 만들기

VS Code에서 빈 폴더 my-site를 열고 아래 구조대로 파일을 만듭니다. 폴더를 먼저 만들고 그 안에 파일을 만드는 순서가 편합니다.

폴더 구조 
my-site/
├── index.html
└── assets/
    ├── css/
    │   └── style.css
    ├── js/
    │   └── main.js
    └── images/
        └── profile.jpg
TIP

이미지는 내 사진이나 직접 만든 이미지를 사용하세요. 지금 사진이 없다면 profile.jpg 대신 색이 들어간 간단한 이미지를 임시로 넣어도 됩니다.

5. JavaScript 작성하기

assets/js/main.js에는 현재 연도를 표시하고, 연락 폼의 빈 값과 이메일 형식을 확인하는 코드를 넣습니다.

assets/js/main.js 
const year = document.querySelector("#year");
if (year) year.textContent = new Date().getFullYear();

const form = document.querySelector("#contact-form");
const statusEl = document.querySelector("#form-status");

if (form && statusEl) {
  form.addEventListener("submit", (event) => {
    event.preventDefault();

    const name = form.elements.name.value.trim();
    const email = form.elements.email.value.trim();
    const message = form.elements.message.value.trim();

    if (!name || !email || !message) {
      statusEl.textContent = "이름, 이메일, 내용을 모두 입력해 주세요.";
      return;
    }

    if (!email.includes("@")) {
      statusEl.textContent = "이메일 주소를 확인해 주세요.";
      form.elements.email.focus();
      return;
    }

    statusEl.textContent = `${name}님, 입력을 확인했습니다. 실제 전송 기능은 서버가 필요합니다.`;
    form.reset();
  });
}
주의

이 폼은 화면에서 입력값을 확인할 뿐, 어디에도 저장하거나 전송하지 않습니다. 실제로 메일을 보내거나 데이터를 저장하려면 서버나 외부 서비스가 필요하며, 서버에서도 입력값을 다시 검증해야 합니다. 05단계의 fetch와 이 저장소의 Java API가 그 예입니다.

6. 이미지 넣기

assets/images/profile.jpg 자리에 내 사진을 넣습니다. 파일명이 다르면 HTML의 src도 같은 이름으로 바꿉니다.

  • 사진은 정사각형에 가깝게 자르고, 가로 400~800px 정도로 줄입니다.
  • alt에는 “프로필 사진”보다 “웃고 있는 사피엔스의 프로필 사진”처럼 구체적으로 적습니다.
  • 프로젝트 이미지를 추가할 때는 카드 안에 <img>를 넣고 width, height, loading="lazy"를 함께 적습니다.

7. 로컬에서 확인하기

VS Code에서 index.html을 열고 Open with Live Server로 확인합니다. 파일을 저장하면 브라우저가 자동으로 새로고침됩니다.

  • 메뉴의 소개·프로젝트·연락 링크가 각 위치로 이동하는가.
  • 창 너비를 360px까지 줄였을 때 가로 스크롤이 생기지 않는가.
  • Tab 키로 메뉴와 폼을 이동할 수 있고 포커스가 보이는가.
  • 폼을 빈 값으로 제출하면 안내 문구가 나오는가.
  • F12 Console에 빨간 오류가 없는가.
  • 이미지가 깨지지 않고 설명이 읽히는가.
참고

운영체제를 다크 모드로 바꾸면 화면 색도 자동으로 바뀝니다. 라이트·다크 모드에서 각각 글자와 배경 대비를 확인하세요.

8. GitHub Pages에 올리기

  1. 저장소를 만듭니다. GitHub에서 새 저장소(my-site)를 만들고 공개 범위를 정합니다. README로 초기화하지 않은 빈 저장소를 사용합니다.
  2. 파일을 올립니다. VS Code 터미널에서 아래 명령을 차례대로 실행합니다. GitHub 주소는 내 저장소 주소로 바꿉니다.
    PowerShell 
    git init
git add .
git commit -m "Create first portfolio"
git branch -M main
git remote add origin https://github.com/내아이디/my-site.git
git push -u origin main
  3. Pages를 켭니다. 저장소의 Settings → Pages에서 배포 브랜치를 main, 폴더를 / (root)로 지정합니다.
  4. 주소를 확인합니다. https://내아이디.github.io/my-site/ 형태의 주소가 표시됩니다.
  5. 1~2분 기다립니다. 배포가 끝나기 전에는 이전 화면이나 404가 보일 수 있습니다.

이미 .git이 있거나 origin이 연결되어 있다면 git init과 git remote add는 건너뜁니다. 저장소를 처음 만드는 명령과 Pages 설정은 08 · 서버 업데이트에 더 자세히 정리되어 있습니다.

9. 배포 후 확인하기

  • 시크릿 창에서 배포 주소를 열어 캐시 없는 화면을 확인합니다.
  • 모든 메뉴와 이미지가 404 없이 열리는지 봅니다.
  • 휴대폰에서 직접 열어 글자 크기와 버튼 크기를 확인합니다.
  • 콘솔 오류와 네트워크 404가 없는지 확인합니다.
  • 수정 후 다시 푸시했을 때 새 내용이 반영되는지 확인합니다.
주의

비밀번호, API 키, 주민번호, 고객 정보는 절대 저장소에 올리지 않습니다. 공개 저장소는 누구나 볼 수 있습니다.

10. 다음 단계

  • 데이터 연결 — 05단계의 fetch로 공개 API나 이 저장소의 Java API를 붙여 봅니다.

  • 360px에서 가로 스크롤 없이 읽을 수 있다.
  • 폼 검증 문구와 현재 연도가 표시된다.

  • 콘솔 오류 없이 로컬에서 확인했다.
  • GitHub Pages 주소로 접속해 메뉴·이미지·폼을 다시 확인했다.
